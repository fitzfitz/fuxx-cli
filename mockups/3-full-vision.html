What you're looking at

  1. Split panesP2M8 Several sessions visible at once. The focused pane has the outline; each pane keeps its own status ring.
  2. Socket API per sessionP2M9 Each session gets a socket path in its environment, like cmux's CMUX_SOCKET_PATH. $FUXX_SOCKET and the JSON shape are illustrative; the real names get decided in M9.
  3. Scriptable automationP3M9 Scripts drive sessions and layout through that socket, e.g. fan one agent out across three repos.
  4. In-app browserP3M10 A browser pane next to your agents, for checking what they built without leaving fuxx.
  5. SSH workspacesP3M10 Sessions on a remote machine, grouped in the sidebar, with the same rings and notifications as local ones.
  6. Remote / tmux-compatible daemonP3M10 Sessions live in a background daemon, so they keep running after you quit and re-attach when you reopen.
  7. A real .app, so notifications say “fuxx”P2M11 Bundled, signed and notarized. Banners show fuxx's name and icon instead of “Script Editor”.
  8. Jump to a session from a notificationP1M11 (D5) Click the banner and fuxx switches to that session. Needs the .app, which is why decision D5 moves it here from M4. Try clicking it.
  9. Install with HomebrewP2M12 brew install --cask fuxx. The cask name is illustrative until M12.
  10. PlatformsP1P3 macOS first and Linux-capable through the Rust stack (P1). Windows support comes later (P3).

Everything from pages 1 and 2 is still here (rings, focus-aware notifications, scrollback, presets…); this page highlights only what Phase 3–4 add.
