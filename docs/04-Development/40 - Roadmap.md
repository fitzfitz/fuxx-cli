- **M11p — Chrome caching** — ⬜ *(after M11y and M11z since 2026-11-13, your call)* added to the plan 2026-11-10 by you, after M11o ("oke, masukkan ke rencana setelah M11o. selama sidebar masih mendapatkan update terkini, saya lanjut"); not designed or planned yet. Follows M11n's "Found for later": the breathing cursor still costs about 5.3 % idle CPU because every breath frame makes GPUI re-render the whole window chrome (sidebar, tab bars, status bar, title area); only the panes are `.cached()`. The idea: keep Rust and GPUI, split each chrome part into its own view wrapped in `.cached()` (GPUI reuses its last layout and paint until that view calls `cx.notify()`), have each part notified only when its own data changes, and keep `Workspace::render` thin (its per-frame work, such as `refresh_right_sidebar`, `tick_right_sidebar`, the window title, ports and the sidebar slide, moves to timers or events). **Your hard rule: the sidebar (and every other chrome part) always shows current information**: agent states, branch and folder, notification rings, ports, names, theme, hover and drag; a part that shows stale data is a bug, and every source of change gets a test. Order: (1) a small prototype that only measures (sidebar and status bar cached, idle CPU with the glow breathing), (2) design with you (brainstorming), (3) a plan, then the build.
