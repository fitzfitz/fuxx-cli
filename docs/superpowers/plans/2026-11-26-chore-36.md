# Chore 36 (after M11ar) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task (the user's build mode: built in the session, screenshots and one review at the end). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The status line's files and checks popovers take the corner popovers' look (one shared piece for all five); the files list groups each folder once, sorted, with files outside the project apart and uncounted; a checks row shows one mark; the plan tab's ◐ follows the files being changed.

**Architecture:** A new `src/agent_popover.rs` (a module of `agent_tab`) holds the look: the frame (`AgentTab::popover_frame`, over `menu_frame_at`), the header (title left, count right), the compact 26 pt row with its 14 pt mark cell, the status marks (`Mark`), the title/mono/tail cells and the quiet footer. The subagents, shells and plan popovers draw through it; the ledger's popover moves out of `agent_box_menus.rs` into `src/agent_ledger_view.rs` and draws through it too. The files list becomes one pure `changed_files::files_list` (changed, scripted and read rows merged, grouped by folder once, inside / outside the tab's folder). The checks' header counts scopes, as the rows do. `plan_progress::mark_done` takes the plan repo's uncommitted paths (read with `git status` in `refresh_plan`'s background read).

**Tech Stack:** Rust, GPUI (pinned), git (porcelain), the ui-shots harness.

**Spec:** `docs/04-Development/93 - Milestone 11ar - Subagents.md`, chore 36 (queued 2026-11-26).

## Global Constraints

- Provider-specific code stays in `src/providers/<agent>.rs`; generic code asks the provider.
- Reuse, no duplication; split files that bloat (`agent_box_menus.rs` 2205 lines, `agent_tab.rs` 7965: new code goes in its own module).
- Neutral example names only (my-app, retry.rs); never the user's paths.
- Per-task gate: `cargo test --bin fuxx`, `cargo clippy --all-targets`, `cargo clippy --all-targets --features ui-shots` (no new warnings in touched files), `cargo fmt --check`.
- Never run `fuxx` by name in a shell; git reads stay off the UI thread.
- The corner tabs' behaviour (when they show, what a row's click does) is unchanged; only the popovers' look.

## Review Focus

- A folder that only a script touched or that was only read, beside one the turn edited (`src` from all three): one `src` group (Task 2 test).
- A tab folder that is a prefix of another (`/w/my-app` vs `/w/my-app-old/x.rs`): outside, not inside (Task 3 test).
- A scope whose latest run has no verdict (piped `cargo build | tail`): one dim mark, never green, not counted passed (Task 4 test).
- The plan file itself is uncommitted while its boxes are ticked: it never makes a task ◐ (Task 5 test).
- A file named by two unfinished tasks changes: only the earlier is ◐ (Task 5 test).
