**Goal:** Auto chosen mid-turn takes effect on the next action (27), a plan answer that approves into Auto (26), chevrons instead of arrow glyphs on the cards' fold links (30), a calmer, shorter permission card (25), a thin blinking caret in the commit box (28), and one inner padding for every text input (29).

**Tech Stack:** Rust, GPUI (pinned), the ui-shots harness.

## Debugging findings (before the fixes)

- **27:** `AgentTab::choose` → `apply_changes` → `step_for(Live, running, spoken, working)`: any change chosen while a turn runs (`Working` or `Waiting`) is `AfterTurn`, held in `self.waiting` until `TurnDone` (M11ak's rule: "a change never cuts the turn"). The picker shows the held mode (`mode_chosen`), but Claude keeps the old mode for the rest of the turn, so its next tool call still asks. The same from a plain session mid-turn; idle, the change was already live. Claude takes the change mid-turn: recorded (`claude-mode-mid-turn.jsonl`, Claude Code 2.1.331), `set_permission_mode auto` sent at the turn's Write prompt is answered `{"mode":"auto"}`, `system/status permissionMode: "auto"` follows at once, and the turn's next Write runs with no prompt; the Agent SDK docs say the same ("takes effect immediately for all subsequent tool requests").
- **26 (protocol):** an `ExitPlanMode` prompt answered `{"behavior":"allow","updatedInput":…,"updatedPermissions":[{"type":"setMode","mode":"auto","destination":"session"}]}` leaves plan mode into Auto: `system/status permissionMode: "auto"` right after, and the Write that follows runs with no prompt (`claude-plan-auto.jsonl`).

## Review Focus

- A mode chosen while a permission card waits (status Waiting) is sent at once, and the card stays answerable (Task 1 test: `step_for` with working = true and mid_turn).

- A permission whose command is one long line (no newlines) isn't cut by the line fold (Task 4 test on `fold_lines`).
- A tool with no readable form (empty `what`) still shows its input, behind "Show input" (Task 4 scene).
